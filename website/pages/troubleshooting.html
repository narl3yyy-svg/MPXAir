Permission denied on a USB port

sudo usermod -aG dialout $USER

Then log out and back in. install.sh offers to do this.

A flight controller connects and then drops

Ubuntu's ModemManager may be probing the device. Stop it:

sudo systemctl disable --now ModemManager

A USB device disappears

If the device vanishes from lsusb and journalctl -k shows error -71, device descriptor read or device not accepting address, the problem is electrical, not software:

  • Try a different, short USB data cable and another USB port.
  • A radio transmitting at high power can draw more current than a laptop port gives. Use external power or a powered USB hub.
  • If a port stays stuck, restart the computer.
journalctl -k -f      # watch while plugging the device in

No heartbeat from the aircraft

  • Check the baud rate: 57600 for most telemetry radios, 115200 for USB.
  • Check that both radios are powered and linked (the radio LEDs should be solid).
  • With a ground station board, MPXAir waits for the aircraft and connects when it appears.

The ground station GPS doesn't show

  • On the Ground tab, check Last message from the ground station. If it's empty, the board isn't sending (try Test now, and check the prefix and poll command).
  • A GPS without a backup battery needs a few minutes for its first fix.
  • The GROUND marker can be hidden with the ground-station button on the Fly map.

No map

Check that Preferences → Maps → Internet use isn't set to Offline. Areas you downloaded with Offline Maps always work without internet.

Some parameters are missing

On slow links a few parameters can be lost. The connection window says some missing. Press Refresh on the Parameters tab to try again.

Reporting a problem

Open an issue on GitHub with what you did, what happened, and the terminal output if you started MPXAir from a terminal.
